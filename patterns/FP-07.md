# FP-07 — evict() Protects Last Item Incorrectly

| field | value |
|-------|-------|
| id | FP-07 |
| kind | classic-operator |
| name | evict() protects last item incorrectly |
| targetFunction | evict |

## What goes wrong

`evict()` caps the number of items that can be evicted at `items.length - 1`, ensuring at least one item always survives. Changing `items.length - 1` to `items.length` removes this floor, making all items evictable. Callers who pass a large count (or `Infinity`) expecting to keep one item will drain the cache entirely.

## Why it hurts in production

Any code path that calls `evict()` to make room while preserving a minimum cache state will instead empty the cache. The next request misses on all keys, causing a cold-cache thundering-herd against the backing store. If `onEviction` callbacks are registered, they fire for the last surviving item, which may trigger erroneous invalidation signals.
