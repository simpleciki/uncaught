# FP-10 — Ascending Iterator Yields Duplicates

| field | value |
|-------|-------|
| id | FP-10 |
| kind | semantic |
| name | Ascending iterator yields duplicates |
| targetFunction | #entriesAscending |

## What goes wrong

`#entriesAscending()` walks `#oldCache` first, skipping any key already present in `#cache` via `!this.#cache.has(key)`. Removing that guard causes every key that was promoted from `#oldCache` to `#cache` to be yielded twice: once from the `#oldCache` walk and again from the `#cache` walk that follows.

## Why it hurts in production

Every consumer of `#entriesAscending()` — including `resize()`, `evict()`, and `entriesAscending()` — builds its working array from the inflated stream. `resize()` and `evict()` compute `removeCount` and `evictCount` from `items.length`, so both counts are wrong: too many items appear to exist, causing the wrong number to be evicted and leaving the cache in an inconsistent state with a `#size` that no longer matches the actual entry count.
