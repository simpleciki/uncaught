# FP-02 — Silent Eviction Suppression

| field | value |
|-------|-------|
| id | FP-02 |
| kind | classic-operator |
| name | Silent eviction suppression |
| targetFunction | #emitEvictions |

## What goes wrong

`#emitEvictions` guards the callback loop with a `typeof` check. Inverting that check (or changing its comparison operator) causes the function to return immediately when an `onEviction` handler *is* registered, and to run the loop when no handler exists — a no-op in either case. No eviction callback ever fires.

## Why it hurts in production

Downstream systems that rely on the eviction callback for cache-invalidation, write-through, or audit-logging receive no signal when entries are displaced. They continue to treat evicted keys as live, causing stale reads, phantom cache hits, or silent data divergence that is invisible until a consistency check or incident post-mortem.
