# FP-05 — Expiry Boundary Off-by-One

| field | value |
|-------|-------|
| id | FP-05 |
| kind | classic-operator |
| name | Expiry boundary off-by-one |
| targetFunction | #deleteIfExpired |

## What goes wrong

`#deleteIfExpired` uses `item.expiry <= Date.now()` to decide whether an item has expired. Changing `<=` to `<` means an item whose expiry equals the current millisecond is no longer treated as expired. Items set with a zero-duration or minimal TTL are never cleaned up because they require exact millisecond equality to expire.

## Why it hurts in production

Items at the exact expiry boundary are served to callers instead of being purged. Rate-limit windows, token leases, and time-bounded feature flags that rely on hard expiry deadlines behave as if they never expire during the transition millisecond, allowing one extra access cycle that violates the intended policy.
