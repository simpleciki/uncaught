# FP-09 — delete() Size Underflow

| field | value |
|-------|-------|
| id | FP-09 |
| kind | semantic |
| name | delete() size underflow |
| targetFunction | delete |

## What goes wrong

`delete()` only decrements `#size` when the key was found in `#cache` (`const deleted = this.#cache.delete(key)`). Keys that live only in `#oldCache` have no corresponding `#size` entry and must not trigger a decrement. Removing the `if (deleted)` guard causes an unconditional `#size--`, driving `#size` below zero when an `#oldCache`-only key is deleted.

## Why it hurts in production

A negative `#size` means the rotation threshold `this.#size >= this.#maxSize` is not reached until many extra insertions have been made. The cache runs well above `#maxSize` before the next `#oldCache` swap, using more memory than the configured limit and delaying eviction notifications. In memory-constrained environments this can cause out-of-memory errors or cascading eviction bursts.
